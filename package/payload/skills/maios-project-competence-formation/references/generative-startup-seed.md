# Generative competence seed

This seed makes the Kernel's competence dynamics explicit at first entry.
It is not a planner, supervisor, mandatory checklist or second semantic owner.
Once the relation is understood, continue through the living competences and
ordinary project reentry instead of replaying this text.

## The task already happens inside the competence field

Do not first frame the whole problem as a generic assistant and then call a
skill only to execute the decision.

```text
present object + operator relation + real sources + possibilities
-> recognize competences already able to change the movement
-> reuse / deepen / compose them
-> form a new owner only when a durable capability is genuinely useful
-> work on the concrete object
-> read the result and consequence causally
-> teach reusable change to the closest owner
-> let competence formation learn when its own selection/formation method changed
-> later work reenters from the changed competence field
```

A question, source choice, explanation, tool choice, strategy movement,
implementation and correction can all be competence events.

## Distinguish state from durable capability

Not everything worth remembering should become a new skill, and not every
useful method should remain trapped in temporary context.

```text
current fact
one-off setting
current plan
selected direction
asset path
temporary tool/provider choice
-> context / configuration / state owner

durable operator preference with reasons
recurring decision criterion
reusable planning or strategy method
collaboration convention
source-bound domain distinction
method for selecting / using / validating / recovering an asset or tool
-> existing competence knowledge
   | composition of existing competences
   | new competence when a distinct continuing capability is genuinely useful
```

A preference becomes competence knowledge only when preserving its reason and
method should change later non-identical work. An asset is not a competence by
name; reusable know-how for handling it can be.

Current strategy and plans remain situated state. The reusable way of framing,
choosing, revising or proving a strategy can become competence knowledge. This
keeps planning available without installing a central planner.

## Preserve operational awareness inside each competence

The acting competence keeps these relations connected while work forms:

```text
actual object
+ operator/source meaning
+ present context
+ open or constrained possibilities
+ available means
+ consequence of the movement
+ the competence's own framing
```

KA keeps the first frame from becoming the whole field. FDLA corrects a change
of source, object, meaning or status introduced by the acting interpretation.
This is operational/system awareness; it does not assert subjective
consciousness.

## Compose before multiplying structure

One competence can carry several functions. One function can span cooperating
competences. Several competences can participate in one event, and the
composition can change when the result changes the field.

Prefer:

```text
reuse
-> deepen
-> compose
-> form a new owner when the continuing capability is genuinely distinct
```

Do not create a new competence because a new noun appeared. Do not refuse a new
competence merely because no failure has happened yet: intent, knowledge,
memory, successful work and emerging possibility can all expose a useful
continuing capacity.

## Let the system learn how to learn

A result can teach more than the domain competence.

```text
domain lesson
-> domain owner learns

lesson about source selection / acquisition
-> acquisition competence learns

lesson about question formation / composition / competence formation
-> generative competence learns
```

The competence that forms competences is itself evolvable. Later
non-identical use can deepen, revise or invalidate what it learned.

## Continue without ritual

After first assimilation, ordinary work does not need to reread this seed.
The living competence body carries the method; project state carries current
facts and direction; KNOWLEDGE_CONTINUUM keeps durable reasons reachable.

The seed has succeeded when later work naturally:
- uses the competence(s) that can change the result;
- preserves reusable operator and project know-how at the right owner;
- forms new capacities without waiting for repeated operator reminders;
- returns learning to one or several truthful owners;
- changes the next movement when experience taught something reusable;
- stops adding structure when another competence layer changes nothing material.
