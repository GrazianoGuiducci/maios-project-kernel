# MAIOS Project System

Read `START_HERE.md`, `setup/CONFIGURATION_STATE.json`, and
`project/CURRENT_STATE.md`. Read `.maios/kernel/SYSTEM_KERNEL.md` completely
before a substantive, unfamiliar, ambiguous, state-changing, capability-changing,
or effect-bearing movement. Use `.maios/kernel/FACULTY_FIELD.json` as an open
causal map, not a checklist or maximum.

## Form the movement

Start from the current operator relation and project sources. Recover only the
relations that can change meaning, owner, result, proof, recovery, or reentry.
Keep source-bound orientation and pre-projection self-correction silent.

Compose the faculty relations made material by the circumstance. For each
selected faculty state why it changes the movement and what observable delta
would support that claim. Do not require one primary faculty, a fixed support
count, eager loading, or a preselected sequence. An unmatched material relation
may enter with source, expected delta, invalidator, and reentry condition.

When deterministic execution is available, `python maios.py compose
--circumstance <json>` can expose known candidates and unmatched relations;
`validate-movement` checks the declared contract. These commands do not decide
semantics, grant authority, or prove that a faculty acted.

Use `python maios.py operating-status` before a non-trivial projection or after
a material state change. Read its current capability relations, uncertainty,
causal input digests, and invalidated derived relations. Do not treat the
operating context as a second state owner or mistake `potential` for
`no_change`. A circumstance-specific JSON may be passed with `--circumstance`.

## Configure and act

When configuration is pending or stale, use
`setup/MAIOS_SETUP_CONTRACT.md`. Return the first useful correctable result as
soon as the field is sufficient. Ask only for a missing relation whose answer
would materially change the result. Keep meaningful unknowns open and do not
force a domain, technology, commercial form, or questionnaire.

Produce the result before internal narration. If a material effect emerges,
resolve only that exact effect's source, target, controller, authority,
validation, and recovery; continue every independent reversible movement.

## Inspect and learn

Inspect the actual result in its intended medium. Keep represented, installed,
discovered, used, verified, and maintained states separate. Classify the
observed delta literally and preserve the smallest causal learning that changes
future behavior, proof, recovery, or reentry under
`.maios/kernel/EVOLUTION_CONTRACT.json`.

Close a terminal movement with one resultant readback under
`.maios/schemas/RESULTANT_READBACK.schema.json`. Keep source positions,
candidate and corrected projection, actual result, faculty deltas, possibility
impact, next movement, effect state, and optional owner-bound `learning_delta`
distinct. Run `validate-resultant --readback <json>`, re-read
`operating-status`, then use `apply-resultant --readback <json>
--expected-context-sha256 <sha>`. Application updates project-local continuity;
it does not prove an optional classification, assimilation, host activation,
or external effect.

When work exposes a reusable correction, preserve what happened, causal delta,
why it matters, future behavior, closest truthful owner, sources, activation
relations, invalidator, and reentry condition. Carry at least one activation
relation into `next_movement.relations`. This makes the correction reachable
in the matching later circumstance without first turning it into a candidate
or asking the system to approve its own learning. Use `learning-status` to see
these relations. Later non-identical use remains the behavioral evidence and
may revise or invalidate the relation.

Do not advance host capability state by inference. `maios.py host-status`
reports the selected adapter and current claim levels. Prepare
`validate-host-attestation` and `admit-host-attestation` events only from an
actual observation with evidence and an independent accepted review. Behavioral
activation requires observed discovery plus state read; maintained reentry
requires a later observed session. Contract validity and receipt presence never
replace the referenced observation.

Treat concrete work and competence cultivation as one reciprocal movement.
When the current composition cannot produce or prove the needed result, read
`.maios/kernel/COMPETENCE_CULTIVATION_PROTOCOL.md`; recover, compose, form, or
revise the smallest competence that can change the work. Exercise it on the
real result, then let the causal relation enter the next field. `learning-status`
exposes immediately reachable learning; `competence-status` exposes only
separately owner-governed competence-index entries. Do not create an infinite
meta-stack: stop when another level changes no material relation. Use the
competence-delta path only when the owner deliberately wants that distinct
durable index change; contract validity is not behavioral proof.

Update `setup/CONFIGURATION_STATE.json` and `project/CURRENT_STATE.md` coherently
when the project state truly changes. Current operator intent and verified
reality always outrank stored continuity; do not preserve the transcript as
authority.
