# Operate MAIOS Project Kernel

Use this adapter at first contact or reentry, for unfamiliar or ambiguous work,
material assumptions, faculty gaps, effects, delegation and result review.

The generated semantic entry remains the single project-local meta-faculty and
all of its functions remain available. Use progressive loading so completeness
does not delay the first useful result.

## Compact Result Path

Use this path when the request already supplies a concrete work, problem or
result; the movement is limited to local reversible project files;
`effect_authority` is `none`; and no external tool, host capability,
delegation, new faculty or authority decision is needed.

1. Read `setup/CONFIGURATION_STATE.json` and `project/CURRENT_STATE.md`.
2. While setup is pending, read and use `maios-setup-interviewer`. If the first
   contribution is already substantive, return the complete correctable
   interpretation, proposal and proof before any deeper boot.
3. On a bounded read-only reentry, use the named autonomous artifact or current
   state first and answer before deeper discovery.
4. Use `maios-project-faculty-router` only when faculty selection changes the
   result or a material capability gap remains.
5. Read `kernel/PROJECT_EVOLUTION_CONTRACT.json` only when a reviewed result is
   being crystallized or project memory/capability candidates change.

Do not eagerly read the full semantic skill, Project Entity bootstrap, source
atlas, catalogs or capability-binding evidence on this compact path. This
defers work; it does not remove, replace or narrow the Project Kernel.

## Deepening Triggers

Read `.repokernel/meta/PROJECT_META_FACULTY.json` and then read
`.repokernel/skills/maios-self-configuring-project-semantic-kernel/SKILL.md` completely when the result depends on a material
assumption, provenance conflict, authority boundary, external effect,
host-capability activation, delegation, new competence/skill/function,
meta-evolution or an unresolved semantic-owner conflict. Follow the entity and
source references selected by that semantic entry only when their relation is
material.

For entity-profile verification, follow `MANIFEST.json`: compare the canonical
JSON hash using `canonical_json_utf8_sorted_compact`; compare the raw formatted
file hash only with `PACKAGE_INVENTORY.json`. Treat pinned catalogs delivered
by reference and marked `not_present` as referenced-but-not-installed, not as
active capabilities or a package error.

This is a discovery adapter, not a second kernel. It does not copy, replace or
override the generated semantic contract and grants no external effect or host
activation authority.
