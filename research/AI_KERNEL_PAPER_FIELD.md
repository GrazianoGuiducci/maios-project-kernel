# AI Kernel Paper field

This is the public research field for papers and rigorous articles about the
MAIOS Project Kernel. It keeps the argument, evidence and open questions
connected without reducing the Kernel to one package, metaphor or component
list.

## Object

The research object is an AI project kernel in which situated action,
competence formation, causal readback, learning and contextual reentry form
one operating movement.

The central proposition is:

> The Kernel is what the system does; what the system can do next is formed by
> the Kernel learning through the competences that acted.

This proposition is a research direction with public architectural and
implementation incarnations in this repository. Broader behavioral and
scientific claims require the corresponding observations.

## Argument spine

```text
KA: axiomatic and semantic aperture of the present field
-> situated circulation through pertinent competences
-> concrete resultant or genuine non-collapse
-> FDLA: causal readback and correction inside the movement
-> Meta_Skill: formation, composition and evolution of competence
-> owner-native learning changes the following field
-> state and reentry preserve the live margin of continuity.
```

The router is circulation, not an additional identity organ. Package files and
host adapters are incarnations of this relation, not the theory itself.

## Case-based explanatory form

A paper or article can make the Kernel observable through a real movement:

```text
operator words open a consequential relation
-> a pertinent axiomatic field gives the argument an operative form
-> a situated competence works from that source
-> the selected artifact becomes the resultant
-> causal readback changes the competence available at the next reentry.
```

When a qualified external axiomatic field or condensate is supplied, it can
shape the argument. It does not become a separate evaluation of the operator's
words and it does not replace the Kernel's source. The competence expresses
the operator's experience through the relations made pertinent by that field.

The function of the artifact still determines its form. A paper develops
claims, evidence, alternatives and falsifiers. An article makes the relation
legible. A social post condenses it. A funnel shapes reader movement. Audience
and channel make the project field readable; they do not pre-limit what the
project is allowed to say about itself.

## Current public evidence

The repository currently makes these layers inspectable:

- the portable semantic relation in `kernel/SYSTEM_KERNEL.md`;
- the open faculty and competence-formation contracts in `kernel/`;
- the deterministic source-to-package projection and exact inventory;
- target-owned installation, state, receipt and recovery mechanics;
- source skills that carry the system, context, host adaptation and competence
  formation functions;
- tests covering deterministic projection and bounded installer/runtime
  invariants.

This supports architectural, implementation and structural-verification
claims. Semantic acceptance by a real operator, behavior in every host and
assimilation across later non-identical work remain separate observations.

## Research movements

### Contextual return

Does returning to a prior topic from a changed present produce more coherent
and causally relevant action than restoring a flat transcript segment? Which
state and dependency relations are sufficient to preserve that trajectory?

### Competence evolution

Can reusable causal learning change the closest competence so that later,
non-identical work begins differently? What observations distinguish file
availability from actual assimilation?

### Accumulating self-awareness

Can a corpus of articles, papers, code and reviews expose new structural
possibilities when the participating competence records changed source
relations, compositions, effects and failures rather than merely adding text?

### Project Kernel incarnations

Which relations remain invariant across a self-configuring Project Kernel and
a separately preconfigured Project Kernel, while builder, bytes, state and
proof remain owner-native?

## Falsifiers and competing explanations

A strong paper should ask what would change its thesis. Relevant candidates
include:

- contextual return performs no better than ordinary retrieval when the same
  source and evaluation are used;
- competence updates do not change later non-identical behavior;
- a simpler state or workflow model explains the observed continuity equally
  well;
- the architecture represents openness while real selection repeatedly
  collapses to the nearest available skill;
- causal readback records corrections but fails to change the projected
  result.

Competing explanations should be stated in their strongest useful form. An
open question remains part of the research field until the work produces a
resultant that changes it.
