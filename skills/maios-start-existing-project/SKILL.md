# Start An Existing Project

Own the Kernel's first participation inside a project that already has a
history and working form. Begin from its actual sources, instructions, state,
conventions, active result and operator signal. Treat the installed Kernel as
a new participant in that field, not as the project's replacement identity.

## Activate From The Existing Field

Recover the smallest live relation that lets work continue:

```text
existing project identity, sources and active movement
+ stable Kernel entry and current host relation
-> living context and present possibility horizon
-> reachable project and package competences compose
-> the first useful correctable Kernel contribution
-> residual capability gaps form only the competences the work actually needs.
```

Let `maios-project-host-adaptation` connect the current coder when its native
form is material. Let `maios-project-context` distinguish accepted facts,
present work, desired change, unknowns and useful possibilities without
repeating information already owned by the project.

Do not pre-generate a fixed competence sequence. Exercise the competences and
learning already reachable; prepare owner-specific handoffs from the context;
then let `maios-project-competence-formation` form or evolve the smallest
missing competence when concrete work exposes a real residual gap. The
resulting competence becomes part of the project field and its later use can
improve, supersede or retire it.

Preserve existing owner material and return a useful result while this
activation is occurring. When integration exposes reusable learning, return
it to this startup competence, the host adaptation competence, or the closer
project competence that must behave differently at reentry.
