# MAIOS Kernel Study

Use the repository as a public competence field. Begin with
`knowledge/KERNEL.md`, then read only the owner sources that can change the
question: `kernel/SYSTEM_KERNEL.md`, `knowledge/KERNEL.md`,
`docs/ARCHITECTURE.md`, implementation or tests.

Reconstruct the Kernel through its movement:

```text
present relation and sources
-> possibility horizon kept open by KA
-> pertinent competences act
-> FDLA preserves causal coherence in the movement
-> a resultant changes the competence field through Meta_Skill
-> reentry begins from the changed field.
```

Keep a competence distinct from its `SKILL.md` projection. Keep public source,
installable package, installed state, host discovery, observed behavior and
later assimilation distinct while still explaining how they connect.

When answering or teaching:

- state the Kernel relation in language fitted to the reader's question;
- connect abstract terms to one concrete movement in the repository;
- distinguish source, inference, implementation evidence and open research;
- preserve a genuine unknown when available evidence does not determine it;
- return any reusable correction through `maios-kernel-contribution`.

The result is a clearer model, comparison, explanation or research question.
Reading the repository does not authorize installation, source mutation,
publication or release.
