# MAIOS Kernel Study

Use `knowledge/KERNEL.md` as the growing compendium of understanding. Connect
its explanations to the current system sources and concrete use. The compendium
is the source reference for the simplification. The installed recipient uses
the existing `.maios/kernel/SYSTEM_KERNEL.md` as its operating compendium,
through the system competence. The source-study skill and this public knowledge
file are not separately added to the package.

Reconstruct the Kernel through its movement:

```text
present relation and sources
+ KA, FDLA and Meta_Skill as the connected operating logic
+ pertinent competences and their knowledge
-> situated work, causal correction and learning
-> continuation from the changed field.
```

Keep a competence distinct from its `SKILL.md` projection. Keep public source,
installable package, installed state, host discovery, observed behavior and
later assimilation distinct while still explaining how they connect.

When answering or teaching:

- state the Kernel relation in language fitted to the reader's question;
- connect abstract terms to one concrete movement in the repository;
- distinguish source, inference, implementation evidence and open research;
- preserve a genuine unknown when available evidence does not determine it;
- teach reusable corrections to the closest owning knowledge body; use
  `maios-kernel-contribution` when preparing a repository contribution.

## Understand the whole through its connections

Whole-kernel understanding connects meaning, operating knowledge, discovery,
context, action, learning, persistence, host adaptation and recovery. It does
not mean loading every implementation file before useful work. Follow a real
movement far enough to explain how those functions cooperate and where the
present implementation diverges from the intended relation.

For the part being understood, establish its purpose, the capability it supplies,
where its usable knowledge lives, what actually reads or invokes it, and what
would be lost or changed if that part moved or disappeared. A short example
should explain how the coder uses or maintains it. A label, directory, schema
or copied description does not supply that understanding by itself.

Several files can carry complementary knowledge. Duplication appears when they
define the same decision independently or make the coder reconstruct it from
conflicting versions. A deeper reference can preserve knowledge without loading
it at every entry. Simplify the relation that causes the repeated decision;
directory depth alone does not determine the useful structure.

Keep visible whether a statement describes source intent, current implementation,
observed use or an unresolved interpretation. An unknown stays attached to the
part it can change, rather than becoming a reason to restart a global audit.
Do not infer that reviewed metadata, a runtime state or a valid schema proves
that the assistant understood or exercised the kernel.

For a transfer-completeness question, also work outward from the source methods:
inspection of the recipient alone cannot expose a function never transferred.
Follow useful knowledge into the delivered body, its actual entry, learning and
reentry. Distinguish a missing method from a differently organized equivalent
and from a capability supplied by the host. A generated project view is not a
durable knowledge owner if its renderer will replace that content. Preserve
the comparison in the owning transfer knowledge, not as a new runtime gate.

## Maintain through the competence that owns the change

When a change is selected, let the responsible competence understand its cause
and follow the changed meaning into its actual consumers. For example, making
an experiment optional includes the entry explanation, configuration acceptance
and the brief shown at reentry; otherwise a remaining "pending" field can ask
the next coder to perform work the project never needed.

Retain the ability to recognize, compose, form and evolve competences while
changing their representation. The kernel's generative method lives in the
formation competence; a map makes knowledge reachable, an index helps recall,
and a runtime transition couples stored state. Each has a different service.
Choose the structure from those services and the receiving host's real needs.

Let this competence learn from its own use: if an explanation leaves the coder
unable to decide where to act, add the missing causal relation to the compendium
or its pertinent reference. If two instructions repeat that relation, give it
one clear source and make the other entry a useful pointer. Preserve the source
meaning and open issues while the structure is being understood.

The result is usable understanding: the coder can explain what its kernel does,
find the knowledge it needs, locate a correction and preserve the capabilities
affected by that correction. Current source understanding remains distinct from
later observed operation in a receiving host.
Reading the repository does not authorize installation, source mutation,
publication or release.
