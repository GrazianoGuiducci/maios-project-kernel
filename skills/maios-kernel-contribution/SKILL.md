# MAIOS Kernel Contribution

Use `contributions/README.md` and the contribution template. Read the public
Kernel knowledge and the closest owner source needed by the proposed change.

The canonical contribution law is functional:

```text
KA keeps the possibility field open
-> present competences compose before a gap is declared
-> a contribution produces or specifies a consequential resultant
-> FDLA corrects source, object, meaning or status deformation in the movement
-> Meta_Skill forms or evolves the smallest competence that carries the
   reusable difference
-> later use may refine, invalidate or assimilate it.
```

A contributor may be a person, GPT Pro, Codex or another capable model. Record
the source relation and model involvement when present; contributor identity
does not establish truth or effect authority.

Create the smallest owner-native change that can alter a later result. It may
be a competence, reference, method, test, falsifier, research delta or source
correction. Do not create a skill merely because a topic has no file.

Every contribution should make these relations recoverable:

- present need or possibility;
- source and claim state;
- closest public owner;
- competence or method body;
- expected or observed delta;
- causal readback;
- invalidator and reentry condition;
- affected surfaces and explicit no-change surfaces.

Validate the actual changed surface. A repository contribution does not by
itself enter `release/PROJECTION.json`, regenerate `package/`, install into a
project, publish a release or authorize any external effect.
