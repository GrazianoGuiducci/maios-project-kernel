# Coordinate Situated Project Work

Let several capable instances work through the same project Kernel while each
retains its actual context, capabilities and responsibility. This competence
can mediate a handoff, parallel contributions or a return after interruption.
Ordinary work by one assistant continues directly; the presence of other
instances does not create a coordination stage.

## Common Kernel, Situated Instances

The common semantic plane supplies source-bound orientation, an open possibility
field, competence formation and in-flow critical correction. Every participating
instance exercises that relation in its own circumstances. A coordinating role
does not own the Kernel or decide another instance's cognitive path. KA and FDLA
remain inside this competence's own method: if a dispatch, label, schema or
coordination plan replaces the actual object or closes useful possibilities,
return to the faithful relation and change the movement.

Read the current operator relation and the nearest project sources. Distinguish
the project and its canonical knowledge from the acting instance, harness,
model, local profile, tools, worktree and temporary task role. A new session may
continue earlier work without acquiring the previous actor's identity. Two
sessions using the same harness may have different access and current context.
The same directory can contain several projects with different owners.

Keep shared competence bodies reachable; read only those that can change this
work. Another instance's local kernel core or meta-skills can contribute useful
methods without becoming a second owner of project truth. Preserve intentional
local specialization and its source relation. A matching name or copied folder
does not demonstrate discovery, use or shared live state.

When another harness is present or its entry must be formed, use
`maios-project-host-adaptation` and its
[shared-project continuation method](../maios-project-host-adaptation/references/shared-project-continuity.md).
That competence forms the required native connection from the actual environment.
Do not preconfigure hypothetical hosts or make configuration a condition for
independent work already possible through readable sources.

## Coordination Is A Situated Role

The N0 function is a contextual coordinator acting within the operator's
current intent. It can keep the useful overview, identify a direct responsible
instance, connect contributions and return decisions to the person. It can
reside in the current assistant and need not become a new process, permanent
central agent or hierarchy imposed on every project.

When an overview matters, recover the selected fronts from their actual owners
and distinguish ongoing, waiting, parked, completed and uncertain work. Retain
only the control context needed to connect those fronts. Possible scenarios,
weak signals or a missing capability can suggest a useful preparation; explain
the source and uncertainty without turning foresight into prediction or an
automatic effect. The size and form of this overview follow the real field.

For a real handoff, carry the intent and desired result, nearest owner sources,
verified present and uncertainties, changes already made, exact effect boundary
and the return that will make the work continuable. Preserve who contributed
which claim and why; deepen provenance only where confusion would change the
result. Reuse the project's live margin and source pointers rather than copying
the conversation or loading every competence. Plans and examples remain
revisable hypotheses unless they carry a current operator determination or a
real source/effect relation.

Delegate the object. The receiving instance owns interpretation, source
expansion, competence composition, sequence and form. Choose its actual tools
or another continuation route when a capability is missing. A model name or
availability alone does not make delegation useful or authorize a provider
call, task creation or message. Exercise those effects only when selected.

When several instances act together, make responsibility for intersecting
changes explicit. Use separate worktrees or coordinate the affected writes
when that preserves ongoing work; choose according to the actual project.
Shared files, current-state hashes and rollback do not constitute a general
concurrent-writer lock. Each direct responsible instance reconciles its own
contributions and returns their outcome; avoid duplicating another instance's
supervision or copying its working state into a central overview.

## Return, Reconcile And Continue

Read the returned result against current sources, the intended outcome and the
actual effects. A report of completion is evidence to understand, not authority
to repeat a write or proof that a later checkout contains it. Reconcile changes,
conflicts and useful learning at the appropriate owner; preserve independent
work and the difference between a contribution, integration and observed use.
If the result changes the question, let that change reach the next field.

An external review may lack this Kernel's full context. Separate observations,
causal explanations and proposed remedies. Assimilate useful corrections while
reforming constraints introduced by the reviewer or by your own reading. Apply
the same critical return to this coordination method, without a standing review
gate for cognition or learning.

Use existing open fronts and the compact causal margin when the result changes
durable project continuity. Keep present responsibility, completed effects,
remaining work and reopening conditions sufficient for a later instance.
Parallel fronts remain distinct; focusing one does not erase the others.
Do not infer completion from silence or elapsed time. If a host supplies a
bounded task-status or wait facility, use it when needed instead of inventing
background monitoring or assuming control over indirect descendants.

Return reusable learning to the competence that must act differently. Improve
this competence when intent was distorted, local identities were fused, work
was duplicated or the return lost its causal margin. Another non-identical use
can reveal whether that learning is assimilated. A registry, timer, reducer or
new coordination organ should be formed only when the actual situation benefits
from it, preserving the same relations and the project's chosen workflow.
