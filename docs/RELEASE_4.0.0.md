# MAIOS Project Kernel 4.0.0

This release makes the maintained RepoKernel-generated competence selection the
ordinary build input. Its source corpus is commit `7c864c4`; the retained plan,
inputs and compiler revision are identified by
[the release selection](../release/GENERATED_KERNEL_SELECTION.json).
The selected corpus and the final versioned builder commit remain distinct.

A complete-checkout reproduction on `c5acf5e` showed that deleting the selection
allowed `python tools/build_release.py` to succeed with a source-only package.
The corrected command fails before replacing the package. Explicit `--source-only`
still builds and verifies the compatibility projection. This is tested through
the real build command, not only the selected_plan function.

## Complete onboarding

Acquisition starts at the repository README and the installable `package/`
README/AGENTS, which reach `maios-project-integration` before installation.
That existing competence recognizes the target project, new/existing mode and
acting host, helps prepare missing Python/model/harness requirements and uses
available evidence instead of imposing a fixed questionnaire.

The ordinary installer previews the exact target and host effect, then applies
the accepted plan. The project retains owner files and recovery. After application,
work continues inside the project through `maios-start-new-project` or
`maios-start-existing-project` and the context competence. An optional integration
handoff uses the existing configuration transition when useful; installer receipts
do not carry semantic conversation or credentials.

Form acceptance is a different entry relation: it supplies context, not proof of
host readiness, installed capabilities or LLM use. The Form release preserves its
own state and delivery process while sharing the generator.

## Evidence and compatibility

The product suite exercises complete builds, new/existing installation, host
entry discovery, configuration/handoff and recovery. These are mechanical
observations. Reachable onboarding instructions and a successful installation
do not establish receiving-model exercise or later assimilation.

The package retains 62 files, including 51 payload files, and its selected seven
competences/eighteen bodies and resources. The shared family stays 3.0.0. Prior
tags remain immutable; no automatic migration from a previous installed product
version is claimed. Source, release artifact and live Form activation have their
own identities and publication records.
