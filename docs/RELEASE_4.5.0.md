# MAIOS Project Kernel 4.5.0

Status: candidate in preparation, 2026-09-14.
Previous stable release: 4.1.2. Project Kernel family: 3.0.0.

## Kernel and entry

The kernel can understand, act and learn in the present context. Its activity
can reform its knowledge, competences and organization. An inquiry, domain,
ongoing activity or project can supply that context. Project initialization
is available through the dedicated startup competences when needed.

The system entry, START_HERE, context, integration and initial continuity now
carry this relation. Formation teaches how to give another context a skill,
mini-kernel or independent kernel with its own practical knowledge, entry,
continuity and ability to form and learn further.

This version also includes the source evolution since 4.1.2: distributed
knowledge, constitutive KA/FDLA participation, acquisition and consolidation,
the relationship between local work and the whole field, and first-use
understanding through concrete examples and their continuation.

## Production and delivery

Installation into an existing empty directory now preserves the directory
itself. It uses the same journalled creation and recovery mechanism as an
existing workspace. This fixes the Windows `WinError 32` reproduced when the
coder's working directory is the installation target. Automatic mode selection,
idempotent reapplication and preservation of concurrent files remain intact.

The current preparation is reconciling the role of the external compiler and
the Form's package composition. The selected design and artifact identity will
be recorded here with the completed build. A prepared source is not a release
tag or a change to an existing installation.

## OpenCode use and ChatGPT review

Install the candidate in a selected local folder through `INSTALL.md`, then
ask the coder to read `START_HERE.md` and continue from the actual intent.
An open inquiry can make a useful first encounter without creating a project.
When useful, follow it into forming a competence or small kernel, learning
from the resulting work and recovering that knowledge in a later session.
Project work remains another available context.

For source review, use `AGENTS.md`, `knowledge/KERNEL.md` and the source bodies
reached from the system competence. Compare their meaning with the delivered
entries and methods. Return a concrete source or received passage with each
useful observation so the next refinement can change the right owner.
