# MAIOS Project Kernel 4.1.0

This release deepens the native kernel's ability to understand its situated
contribution and continue the reasons behind decisions. The system competence
relates project purpose, reachable knowledge and the current instance's actual
means. Context can change through successful work, new sources and emerging
possibilities as well as failures. Competence formation carries those relations
into the methods it forms; knowledge continuity connects observed effects,
conditional consequences, expectations and the following situation.

These methods live in the existing system, context, competence-formation and
knowledge-continuity bodies. They remain reachable through the same native host
entries. No extra supervisor, identity store, mandatory interview or background
process is installed.

## Repeatable production

`tools/renew_kernel_selection.py` forms the maintained generation inputs and
plan from explicit product and compiler commits, then the existing ordinary
builder produces the package. The selected compiler is RepoKernel
`334a9d33c12d61ba826d41b25f604af18441e967`, 0.4.0.dev5.
The exact method corpus is recorded in `release/GENERATED_KERNEL_SELECTION.json`.
Read [the renewal method](RENEW_KERNEL_SELECTION.md) for future updates.

The separate historical entity-profile basis remains identified in the manifest.
Its current product translation preserves the open, deferred-context entry;
adopting a new compiler for methods does not falsely relabel that provenance.
The shared Project Kernel family remains 3.0.0.

## Acquisition and use

The full 4.0 onboarding remains available: instructions before installation;
recognition of the project and actual host; preparation of missing requirements;
preview and exact application; project startup and context formation; useful
work, knowledge evolution and reentry. Existing-project installation continues
to preserve conflicting content. Host discovery uses the existing native
adapters and living skill pointers.

A receiving project needs a capable agentic harness and Python 3.10 or later
for installation and deterministic helpers; it does not need RepoKernel or
third-party Python packages. Package generation and integrity do not establish
receiving-model use or assimilation. The current operator can continue from
the available evidence and learn from actual use without another prescribed
experiment.

For an installed project that has evolved, use the existing UPDATE_CONTINUITY
method to compare its baseline, local knowledge and the proposed update. This
release is not an automatic migration or an overwrite of learned methods.

## Website and communication handoff

continuity and repeatable source generation. The Form 0.13.1 is a separate
consumer release; its accepted context is not included here. The public versioned
release supplies the acquisition artifact. Avoid claims of tested subjective
awareness, universal host activation, unattended self-updating or migration.
The release receipt records the exact source, artifact and checks separately.
