# MAIOS Project Kernel 3.1.0

This minor release gives the autonomous Project Kernel a continuing knowledge
and learning relation across sessions. Competences carry living knowledge,
reasons and method; relevant sources remain reachable at fresh reentry, while
superseded knowledge can leave active recall without losing its genealogy.

The accumulated changes include:

- plural learning ancestry, cooling, retirement and reopening, with later use
  attributed to the relation actually exercised;
- persistent selected knowledge references, attributable and correctable
  intent, and source-contact attempts and successful observations;
- native entries that read current competence bodies and a plan-bound initial
  update baseline that preserves the distinction from local project evolution;
- canonical installation, configuration and operating contracts v3, with
  learning relation v2;
- conservative interrupted-installation recovery: a complete validated journal,
  exclusive creation evidence, qualified file identity and preservation of
  uncertainty, backups and already committed installations;
- uninstall bound to the valid current plan, including explicit receipt copies,
  and preservation of existing-project directory ownership;
- canonical source-contract hashing, keeping the complete package identity
  identical across LF and CRLF checkouts.

Both reviews of continuum.4 close its two pending-recovery blockers. One also
identified the stale uninstall receipt and empty-directory defects corrected
in this release. Three regressions exercise those cases in real generated
artifacts; the full suite contains 58 tests. The distribution contains 58 files,
including 47 payload files. The release workflow verifies both Ubuntu/Python
3.10 and Windows/Python 3.13, deterministic rebuilding and exact projection.
The workflow result must be read on the exact release commit.

The shared Project Kernel family remains 3.0.0. The tracked `package/` directory
is the installable projection, as in earlier releases. No separate release
asset is needed. Begin with the repository README and `package/INSTALL.md`.

The update standard starts with its first users. The installer does not perform
automatic cross-version migration; later target-owned updates reconcile the
original baseline, local learning and selected source changes.

Installation mechanics, real native host use and later non-identical
assimilation retain separate evidence levels. The latter two remain unobserved.
The Form package, site and unified chat/harness work retain their own next
movements and are not advanced by this autonomous product version.
