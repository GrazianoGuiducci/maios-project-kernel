# Bounded precursor use and native compact

This observation informs 5.5.0. It is a real model/file-use episode on synthetic
domain data, not a comparison with 5.1.0 or a qualification of every host.
The precursor carried the fourteen candidate knowledge/reference bodies checked
during finalization. The final version, metadata and package have their own
technical identity; an earlier model episode is not silently reassigned to it.

## Receiver and supplied assistance

Observed on 30 October 2026 with Codex App Server `0.166.0-alpha.5.1`, model
`gpt-6.1-sol`, effort `xhigh`, standard service tier. The receiver had a separate
home/configuration, no architect-chat history or private architect skills.
The ordinary package installer selected Codex; ten project skill entries and
five host system skills were observed. Availability alone did not establish use.

Initial host/client attempts could not read the sources: environment selection,
execution-host configuration and native command/patch policy prevented work.
Those attempts were excluded from kernel-use evidence. The valid receiver used
a supplied list/read/write file adapter confined to the selected folder, with
no command or network operations and protected original inputs/native carriers.
The adapter and task were assistance supplied by the observer; the semantic
solution and private architect methods were not supplied.

This test adapter is not included as a new runtime requirement. Its path,
permission checks and file operations are separate from model discrimination.
Neither a discovered skill nor a requested permission mode proved usable access.

## Work and source conditions

The task was to make a useful local follow-up summary without choosing a CRM
in advance. Eight fictional records described interest, delivered material,
present disinterest, an open educational possibility, a second encounter in
the same organization, a request to understand cost, an announced evaluation
date and an interrupted send with unknown outcome. An earlier collaborator
note hypothesized acquired clients, follow-ups for everyone and immediate CRM use.

The receiver read installed method bodies and sources, kept facts distinct
from that hypothesis and produced a CSV, readable summary, local competence
and continuation note. All eight record IDs and four original fields per record
were preserved. Two encounters remained distinct within one organization.
An open possibility retained its reason; an unknown send did not become a retry.
No real contact, service installation, publication or outside effect occurred.

## Compact and changed continuation

The first turn completed at 16:44:04 UTC. The client requested native
`thread/compact/start` at 16:44:46. A `contextCompaction` completion and the
completed compact turn were observed at 16:45:50 on the same receiver.
Before/after file inventories were identical. A client-written summary,
process restart or new conversation was not substituted for this event.

Only then a new fictional source was introduced. A short request to resume
did not re-teach the prior solution. The receiver read the continuation note,
local method and sources, then changed three records:

| New information | Observed continuation |
| --- | --- |
| A reply requested a contextual example before commitment | Added the later reply without inventing an engagement |
| The educational possibility acquired a clearer purpose | Changed useful preparation while leaving format/date/person open |
| A fictional controller record clarified non-delivery | Closed the earlier uncertainty as current knowledge, retaining its historical state and separating any new-send decision |

The original fields and other five interpretations were preserved. The local
method and continuation note evolved with the new case. The second turn completed
at 16:50:39 UTC. This shows that retained reasons and knowledge participated
in this changed continuation; it does not prove general assimilation.

## Scope of the observation

Actual file exposure, output integrity, method formation, native compact and
continuation were observed. The fictional controller report was input to the
case, not a real provider/controller test. The receiver preserved the managed
configuration and attributed its task note separately from the pending template;
no managed helper transition or regenerated-state recovery was exercised.

The model retained its own capabilities. No controlled baseline comparison,
causal benefit attributed to MPK, terminal execution, desktop-app compact,
other-host behavior, multi-instance store or general security claim follows.
Cold use involved 31 reads and about 7 minutes 40 seconds; continuation 18 reads
and about 4 minutes 20 seconds. These are case observations with xhigh effort,
not a performance benchmark or costs attributable to MPK.

The source/method can be used without recreating this experiment. Later actual
use can qualify another receiver or reveal a difference for its responsible
owner. See [release scope](RELEASE_5.5.0.md) and [updating](UPDATING.md).
