# MAIOS Project Kernel 4.1.1

The installed Kernel can prepare useful feedback from a first meaningful use
or later source contact: friction, confusion, failure, unexpected success or a
new possibility. It shows the proposed public-safe text to the operator and
requires consent before sending it. Observations go to an upstream Issue;
a concrete correction can be proposed through a fork and focused Pull Request.
If the host cannot submit, it returns the prepared text without claiming a send.
Feedback is optional and informative, not a periodic reporting obligation.

Source contact retains its light, roughly seven-day cadence during active use.
It considers upstream main as well as version and release, since useful source
changes can precede a new tag. A newer source is a proposal to understand, not
an automatic pull, installation or overwrite of project knowledge.

## Delivery and updates

The maintained production selection renews the existing system competence and
UPDATE_CONTINUITY method. Their exported and packaged bodies must match the
selected source; a green metadata-only rebuild would not establish delivery.
The existing runtime, host adapters, recovery and family 3.0.0 are preserved.
The package still requires Python 3.10 or later, with no third-party packages.

This release does not migrate existing installations. Their original baseline,
local knowledge and proposed update are reconciled through UPDATE_CONTINUITY.
Source publication or package generation does not establish receiving-model use,
submission of feedback, or assimilation.

[Source and distribution evidence](RELEASE_4.1.1_EVIDENCE.md) records the selected
corpus, exact delivered bodies and validation. Versioned release assets identify
the available package; release publication remains distinct from host adoption.
